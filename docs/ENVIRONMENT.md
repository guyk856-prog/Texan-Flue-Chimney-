# Environment settings

Set production values in **Vercel → project → Settings → Environment Variables**. Do not commit `.env`, paste secrets into chat, or put secrets in variables beginning `NEXT_PUBLIC_`. Safe examples below are intentionally unusable credentials. Use a password manager to generate separate random 48-character values for authentication and first-run setup. Changing the authentication secret signs everyone out.

| Variable                              | Status                                                  | Safe example                                                                                                                     | Purpose / what happens without it                                                                                                                                                                                                                        |
| ------------------------------------- | ------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `DATABASE_URL`                        | REQUIRED                                                | `postgresql://USER:PASSWORD@ep-example-pooler.us-east-1.aws.neon.tech/neondb?sslmode=require&connection_limit=2&pool_timeout=20` | Pooled runtime connection. App reads/writes fail without it.                                                                                                                                                                                             |
| `DIRECT_URL`                          | REQUIRED                                                | `postgresql://USER:PASSWORD@ep-example.us-east-1.aws.neon.tech/neondb?sslmode=require`                                           | Unpooled connection for migrations, deployment lock and backups. Deployment stops without it; a pooler hostname is rejected.                                                                                                                             |
| `AUTH_SECRET`                         | REQUIRED                                                | `GENERATE-A-NEW-RANDOM-48-CHARACTER-SECRET`                                                                                      | Encrypts session cookies and signs download links. Build stops if fewer than 32 characters.                                                                                                                                                              |

Vercel supplies `VERCEL`, `VERCEL_ENV`, `VERCEL_URL` and `VERCEL_PROJECT_PRODUCTION_URL` automatically. Do not create them manually. `NODE_ENV` is supplied by Next.js/Vercel; do not override it. `DATABASE_URL` and `DIRECT_URL` for Preview must point to a separate Neon branch, never the production database.

## GitHub backup secrets — not browser or application settings

Under **GitHub → repository → Settings → Secrets and variables → Actions → Secrets**, add:

| Secret                          | Status                              | Safe example                                           | Purpose / missing behavior                                                                                                                                    |
| ------------------------------- | ----------------------------------- | ------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `BACKUP_DIRECT_URL`             | REQUIRED for nightly backups        | Same form as unpooled `DIRECT_URL`                     | Consistent PostgreSQL export. Job fails if absent.                                                                                                            |
| `BLOB_READ_WRITE_TOKEN`         | REQUIRED for nightly backups        | Private application-store token                        | Reads private originals/PDFs into the encrypted backup. Job fails if absent.                                                                                  |
| `BACKUP_BLOB_READ_WRITE_TOKEN`  | REQUIRED for nightly backups        | Token for a **separate private backup store**          | Stores encrypted backup archives. Job fails rather than claiming an ephemeral runner copy is a published backup.                                              |
| `BACKUP_PASSPHRASE`             | REQUIRED for backup/recovery        | `GENERATE-AND-SAVE-A-SEPARATE-48-CHARACTER-PASSPHRASE` | Derives AES-256-GCM encryption key using scrypt and a random salt. Keep an offline/password-manager copy; losing it prevents recovery. Minimum 32 characters. |
| `RESTORE_DIRECT_URL`            | REQUIRED only for recovery workflow | New empty Neon database direct URL                     | Recovery refuses a database containing application tables.                                                                                                    |
| `RESTORE_BLOB_READ_WRITE_TOKEN` | REQUIRED only for recovery workflow | New empty private-store token                          | Recovery refuses a nonempty store.                                                                                                                            |

Set the Actions **variable** `PRODUCTION_BACKUPS_ENABLED=true` only after the secrets exist and a manually triggered backup/restore drill succeeds. The scheduled job otherwise stays skipped; skipped is not a backup. Optional `BACKUP_RETENTION_DAYS` defaults to 30, minimum 30, and only prunes old archives after a successful restore check. The document retention policy and the disaster-recovery backup window are separate policies.

Recovery workflow inputs: `backup_name` is a filename such as `backup_20261102032815306.bin`; `confirmation` must be `RESTORE TO EMPTY TARGET`. These are not connection strings. The optional operator CLI bootstrap uses `OWNER_EMAIL`, `OWNER_NAME`, `OWNER_PASSWORD` in a secure shell; the normal owner uses the browser setup and needs none of those variables.

## Developer-only audit/test settings

`ACCESSIBILITY_SESSION_FILE` is OPTIONAL for the standalone Lighthouse script (default `private/accessibility-session.json`); it points to a Playwright storage-state file containing an authenticated test session. Missing file stops the audit. Keep it ignored and use demo data. `PHASE_E_DATABASE_URL` is OPTIONAL and normally generated by the test configuration; only a disposable database named `texan_e_<digits>` is accepted for creation. `PHASE_E_BASE_URL` is generated internally as the isolated test-server origin. `CI` is OPTIONAL and supplied by CI runners to prevent reuse of a development server. None belongs in the owner's Vercel settings.

The operating system supplies `HOME`, `PATH`, `TMPDIR` and optionally `XDG_CACHE_HOME` for local worker/browser discovery. Leave them alone; no production configuration is needed.
